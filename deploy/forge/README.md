# Isolated Forge retrieval image

This recipe builds the checked-in fork source, not an npm release. It targets
Linux amd64 and pins Node 24.14.0, iii 0.11.2, the npm dependency closure and the
MiniLM model revision. Run `sh deploy/forge/build.sh` only after the reviewed
changes are committed: the build context is `git archive HEAD`, and the image
tag and OCI revision label contain that exact commit.

The scoped lockfile is generated from the repository package.json using
`npm install --legacy-peer-deps --ignore-scripts`. The root lockfile policy is
unchanged. To refresh this recipe, regenerate the lock, review dependency changes
and update `deploy/forge/package-lock.json` together with package.json as needed.

The build fetches model assets from revision
`751bff37182d3f1213fa05d7196b954e230abad9` of
`Xenova/all-MiniLM-L6-v2`, records their SHA-256 hashes inside the image, and runs
a local 384-dimension embedding check with remote model loading disabled. Model
files and dependencies live in the image, separate from the writable data volume.
No inference API key is required or accepted by the entrypoint.

Runtime requirements:

- A new volume at `/data`, writable by uid/gid 1000. No host home, personal
  `.agentmemory`, personal store, Docker/Podman socket or project source mounts.
- An explicit `AGENTMEMORY_SECRET` service credential. It is never printed or
  generated by this image. Never put its value in the image or a committed file.
- An internal container network with outbound internet denied. Expose only REST
  to Forge; for a host Core publish an unused host loopback port, e.g.
  `127.0.0.1:3211:3111`. Never replace the personal daemon's port or volume.
- Runtime init/signal forwarding (for Podman, `--init`). The existing iii-exec
  worker runs the built AgentMemory index module; no CLI auto-installer or
  interactive onboarding runs in the container.
- Configure the orchestrator's liveness probe against `/agentmemory/livez` on
  REST, allowing local model startup time. OCI images do not retain Docker's
  `HEALTHCHECK` instruction; a successful liveness probe is not indexing readiness.

The entrypoint forces automatic compression, forgetting, consolidation, graph
extraction, snapshots and context injection off. It strips inference credentials
and loads embeddings from the packaged files with remote loading disabled.
The home directory belongs to the clean container user; do not mount it.

Image build and `/livez` alone are not acceptance. On the dedicated instance,
verify strict import, compact search, repeat/upsert, forget, service restart and
read-back while external egress is denied. Keep canonical entries, visibility,
revision/hash validation and deletion tombstones in Forge PostgreSQL.

The pinned dependency set currently reports npm audit findings inherited from
the source package. Dependency upgrades require a separate review; this recipe
does not claim those findings are remediated.
